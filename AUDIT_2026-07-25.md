# D4SG @ SA — Polish & Alignment Audit (2026-07-25)

Comprehensive audit + refinement pass. Ground rule: preserve all functionality, refactor and polish only. Five parallel audits (UI/cognitive load, content alignment, module flow, rubrics/scoring, Tools deep-dive) followed by one implementation pass. All functionality verified in-browser after the changes: home, tools, all three tools mount/unmount cleanly, progress cards render live data, zero console errors.

## The headline numbers

- index.html: **19,965 → 16,115 lines (−19%)** with zero functionality removed — everything deleted was verifiably unreachable.
- One blocking 390 KB CDN script (Konva) removed from every page load.
- 5 high-severity tool bugs fixed, including two silent data-loss paths.
- 170 dead CSS rules, ~1,900 lines of dead CAD tool, ~940 lines of dead legacy Idea Board, the dead Project-0 accordion, and the dead class-code gate removed.

## 2. Tools — bugs found and fixed (priority area)

**Silent data loss (worst finds):**
- `schemRender()` was called in two places but **never existed** — a student's cloud-synced schematic downloaded correctly and then never painted, so a new laptop showed a blank board they could accidentally overwrite. Both sites now call `renderPerfboard()`.
- Resized breadboards used a static 13-row pin table for wire lookups — wires drawn on grown rows were saved but never drawn again after reload. Pin lookup now generates from the actual row count.
- Schematic keyboard shortcuts stayed live app-wide after leaving the tool: pressing R/Delete/Cmd+Z on the Homework page silently rotated/deleted/rewound the saved schematic with zero visual feedback.

**Root cause fixed once:** `applyRoute` had no teardown hook. Added a single per-view teardown that every view registers into. It now: closes any open modal on Back/nav, removes all schematic document listeners, releases the Web Serial port, disposes Monaco, unmounts the Excalidraw React root, stops the two class-wide Progress listeners, and destroys the roster listener behind each identity strip. This one hook resolved eight separate leak/duplication bugs.

**Vibe Coding:**
- Upload button permanently died after any compile failure (broken `finally` guard) — every student's first typo bricked Upload for the session. Fixed.
- After a successful upload + auto-reconnect, the serial Send box stayed disabled — this blocked the exact `set port N to <action>` workflow p4b4 teaches. Fixed.
- AI requests now abort after 75s (a dropped wifi connection used to wedge the composer shut permanently); `_vibeBusy` also resets on mount.
- Rate-limit/too-long/forbidden errors now show the server's real message instead of a contradictory "try again"; 429 adds "Verify and Upload still work."
- Connect button ignores double-clicks while the port picker is open; monitor Send drops keystrokes while a write holds the stream lock; chat no longer force-scrolls when you've scrolled up to re-read wiring steps; focus is no longer yanked back to chat if you're working in the editor.
- The compile function is pre-warmed on tool mount (GET health ping) so the first Verify of a period skips the cold start.

**Schematic:**
- Palette drag cancels before placing (double-drop guard), drags survive leaving the canvas (listeners moved to document), rotated parts keep their rotation while dragging, duplicate wires between the same pins are refused, Escape cancels an in-progress wire, undo skips no-op snapshots so Cmd+Z always visibly does something, saved PNGs no longer bake in the red delete-X/selection halo, quota-full saves toast instead of failing silently, "Clear canvas" copy now honestly says undo works.

**Idea Board:** React root unmounts on route change (was leaking a full Excalidraw tree per visit).

**APIs:** `compile.js` gained the same origin gate + reflected CORS as `vibe-code.js` (was `*` with no gate — anyone could drain the class compile quota); anonymous students no longer share one `_anon` 200/day bucket; `vibe-code.js` checks the API key before consuming rate-limit quota.

## 3. Content alignment

- **Restored authored-but-invisible content:** all five project `goal` paragraphs (the "builds on the last project" narrative) were dead data — the renderer read a `blurb` field that never existed. Portfolio benchmark `instructions` were silently skipped by a title-based gate (including the p4 persona-adoption requirement the rubric grades). Both render now.
- **Prompt ↔ rubric gaps closed (prompt side, grading untouched):** Instructable intro now asks for user + need in ≤3 sentences; Materials asks for total build cost; Build Steps ask for parts + pins; Video asks for end-user motion + remap app — all things the Mastered rubric level already graded.
- **Curriculum contradictions fixed:** the required arm/disarm switch is now explicitly exempt from each Product benchmark's stated component maximum; the Instructable's "complete Submit below" now names the actual "Drop your Instructable link" section.
- **p4b2 is now buildable as written:** added the 3.5mm jack and JST-XH header to the Schematic palette (the step required drawing parts that only existed in the Idea Board).
- **One vocabulary:** Idea Board stamps renamed to match the curriculum (Sip-and-Puff, Capacitive Touch, Distance Sensor); Tools card blurbs rewritten to describe what the tools actually do (breadboard-first schematic; stamps not Konva-era "callouts"); syllabus "Arduino IDE" requirement corrected to Chrome/Edge + Web Serial; modal eyebrow for Project 0 rows says "Video" instead of leaking a project name into a type slot.
- Homework points are now data (`points: 5` on each week) instead of two unrelated hard-coded strings.
- Verified clean: all internal `tools#…` links resolve; all 20 YouTube IDs unique and present; no placeholder URLs.

## 4. Module flow & navigation

- Back button / top nav can no longer leave a modal stacked over a new view with scroll locked.
- Navigating Home from `/?b=…` actually clears the deep link (path+query compare), and closing a benchmark modal removes `?b=` from the URL so refresh doesn't resurrect it.
- The home tab now live-syncs checkmarks from the work tab (`storage` listener) — completing a benchmark finally shows up without a manual reload.
- Tool-launcher links are wired wherever they appear (the Brief section's links previously rendered but did nothing).
- `?b=` deep links now also resolve homework weeks, and unknown ids get an honest toast instead of a silent home render.
- Saving a tool artifact to a Project 0 benchmark used to silently discard the file — Project 0 is now excluded from the Save-to menu, and an unresolvable target clears the pending artifact with a toast instead of stranding a Blob.

## 5. Rubrics & scoring

- **All 26 rubric point sums verified arithmetically correct** (P0 5×2, P1–P4 each 4×2 + 50-pt portfolio summing exactly, Instructable levels summing to 100). No grading math changed.
- Submission-count badges no longer count soft-deleted work (total minus deleted, two cheap aggregates).

Broken-image fallbacks route through two tiny helpers so even error states use the icon family. (One ⚠ remains by design: terminal-style text inside the serial monitor log, next to ✓/✗.)

## Deliberately NOT changed (needs Ramsey's call — see proposals)

1. **Portfolio resubmits fragment into multiple docs** (`addDoc` per submit). The fix — deterministic `benchmarkId__studentSlug` doc ids with merge, like the Instructable already uses — is ~4 lines but changes the data model mid-course, so it ships only with approval. This is the single biggest grading-workflow win available.
2. **The progress meter counts benchmarks, not points** — finishing all 20 checkpoints (40 of 342 pts) reads as 77%. Weighting it by points is a one-line change to what the bar *means*, so it's a policy call.
3. **One filled slot marks a 50-pt Portfolio "done"** (green pip identical to a complete one). Options: partial-fill pip, or gate on slot count.
4. **The local checkbox is device-local and never reconciles with Firestore** (shared laptops show the previous student's checks). Fix = derive from Firestore per picked name; wipes nobody's data but changes what checks mean.
5. **Syllabus weights** say ~50/25/25; encoded points compute 58/18/24. Which is authoritative?
6. `firestore.rules` has an uncommitted, unrelated Surf Check journal diff from another session — left untouched and uncommitted.

## Proposals: simplest-yet-most-interactive next steps (build only on approval)

1. **"Up next" ribbon on home** — one quiet card at the top: your next unfinished benchmark, one click in. Kills all scanning; the page opens with exactly one obvious action.
2. **Deterministic portfolio docs** (item 1 above) + grader-friendly single row per student.
3. **A tiny points engine** — the rubric data is already perfect; ~30 lines would put an honest "128 / 342 pts" on each progress card and make the meter mean something. Pairs with #2.
4. **Per-project mini-meters on home** (`3/5` beside each project title) so progress is visible where the work happens, not only on /progress.
5. **Benchmark → tool round-trip** — launching a tool from a benchmark currently loses the way back; a "Return to Button" chip in the tool header (state already exists) closes the loop.
6. **AI & ML twin re-sync** — everything in this pass applies to the twin, which hasn't been re-synced since April and (per the July audit) has broken Firestore rules. One port session covers both.
